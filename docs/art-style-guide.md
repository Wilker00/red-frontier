# Red Frontier Art Style Guide

## 1. Core visual direction

Red Frontier should use a stylized 2D top-down visual language with strong silhouettes, readable symbols, and a premium sci-fi-industrial feel. The goal is not realism. The goal is clarity, trust, and a confident operations-sim aesthetic.

The game should feel like a polished mission-control interface set inside a warm, readable Martian landscape.

## 2. The look and feel

- Stylized, not photorealistic
- Clean silhouettes
- High contrast between units, terrain, and UI panels
- Clear readability at a glance
- Strong industrial design for equipment
- Warm Martian terrain anchored by cool tech accent colors
- Friendly but serious tone suitable for a learning and collaboration game

## 3. Reading and clarity rules

Every object in the world should be instantly readable from a distance:

- robots must have a unique silhouette and marker
- resource nodes must stand out
- charging stations must glow
- habitat construction sites must visibly progress
- selected units must have a clear outline or callout
- mission-critical warnings should use both icon and text

Do not rely on color alone for system meaning. Use labels, icons, and symbols alongside color.

## 4. Color palette

### Terrain
- Sandstone: #D9A06C
- Rust red: #A6543F
- Dark basalt: #2F2423
- Dust beige: #EBD5B3
- Slate gravel: #6F5E52

### Equipment and UI
- Steel: #5B6875
- Graphite: #1E2A33
- Copper accent: #D78A4C
- Signal blue: #58C4D9
- Power cyan: #79E0D7
- Alert red: #D65A5A
- Success green: #7FD9A0

### Background / panels
- Deep navy: #101A22
- Panel dark: #1B2933
- Shadow black: #0C1216

### Use rules
- Warm terrain should dominate the map
- Tech and interface elements should use cool, crisp contrast
- Important gameplay states should use bright accent colors without overwhelming the map

## 5. Visual hierarchy

The game should be structured so the player can parse the world in 3 layers:

1. World layer
   - map tiles
   - resources
   - robots
   - obstacles
   - buildings

2. Interaction layer
   - selection outline
   - status rings
   - charging indicators
   - build progress glyphs

3. Interface layer
   - HUD
   - mission checklist
   - logs
   - resource totals
   - robot details

The world should never feel crowded. The interface should feel like a control room, not a noisy arcade menu.

## 6. Robot and unit design

### Rovers
- compact and industrial
- clean chassis silhouette
- visible wheels or tracks
- small highlighted front direction indicator
- subtle glow on active or charging states
- separate color marker for each player

### Habitat structures
- modular, blocky, assembled architecture
- build pieces should stack logically
- power connection should be visually obvious
- progress should show as completed segments or glowing nodes

### Resources
- metal nodes: angular, dense, metallic forms
- ice nodes: crystalline, cool blue, framed with subtle glow

### Charging stations
- circular or hub-like station
- strong center glow
- subtle pulse when active
- clear visible connection line to a rover when charging

## 7. World tiles and map design

Use a small library of repeated tiles:
- dusty flat ground
- rocky pass
- crater edge
- charging pad
- base tile
- construction site
- blocked terrain

Keep tiles legible and not too visually noisy. The map should support quick scanning at a glance.

## 8. UI style

### Layout concept
- top bar: mission title, room code, team status
- left panel: objective checklist and resource data
- center: map world
- right panel: code editor, logs, selected robot panel
- footer: event strip or action log

### Panel style
- dark panel backgrounds
- warm accent lines
- subtle gradients
- preserved whitespace
- strong iconography
- coordinate labels and status tags

### Buttons and interaction
- primary actions should use a strong accent color
- hover states should be obvious and soft
- disabled states must still feel legible
- selection should use high contrast, not just a subtle shadow

## 9. Motion and effects

Use animation to communicate system state, not to decorate the world.

- mining dust particles
- charging pulses
- movement trails
- construction glow
- low-battery warning flicker
- selected robot ring pulse
- resource collection pop effect

Keep effects readable, subtle, and consistent.

## 10. Production approach for the deadline

For a 4-week delivery, do not create fully custom art for every object. Instead:

- use a clean stylized asset base
- adapt palette and silhouettes to fit the game
- make a small set of custom terrain tiles and player-specific rover markers
- invest in UI polish and readability
- favor a cohesive style over large visual variety

## 11. Recommended art package strategy

Use a hybrid method:
- base industrial/scifi props from free or cheap packs
- custom Mars terrain and panels
- custom robot silhouettes and mission icons
- a consistent color palette
- a small number of high-quality build assets

This yields a polished look without requiring a full art team.

## 12. Reference intention

The target is a polished, readable, slightly industrial sci-fi game that feels “premium and practical,” like a tactical operations sim in a browser. It should feel confident and modern, not childish or overly realistic.

The strongest visual decision for Red Frontier is this:
- world: warm, readable, Mars-like
- infrastructure: clean, industrial, easy to understand
- UI: sharp, mission-control style
- all objects: high contrast, strong silhouettes, low clutter

## 13. Asset investment priorities

Priority 1: rover silhouettes and player markers
Priority 2: terrain tiles and props
Priority 3: base and habitat building pieces
Priority 4: HUD icons and mission log panels
Priority 5: particle effects and polish

## 14. Final design statement

Red Frontier should look like a polished browser strategy game set on Mars: clear at a glance, industrial in structure, warm in color, and strong in silhouette. The art should support the teaching and cooperation goals of the project by making game state immediately understandable.
